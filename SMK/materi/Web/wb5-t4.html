Rapikan dan Dokumentasi

Merapikan indentasi baris kode dan menulis dokumen README yang menjelaskan karyamu

Materi Lengkap: Pengembangan Halaman Web

Konsep dasar. Pengembangan web menggabungkan struktur halaman, tampilan, dan perilaku interaktif. HTML mendefinisikan makna dan struktur, CSS mengatur presentasi, sedangkan JavaScript mengatur logika di browser. Pada materi Rapikan dan Dokumentasi, fokus utama kita adalah pengembangan halaman web. Tujuannya bukan menghafal langkah, tetapi memahami alasan di balik setiap keputusan sehingga kamu dapat menerapkannya pada masalah yang berbeda.

Cara kerja. Halaman web dibangun dari struktur HTML, aturan visual CSS, dan perilaku JavaScript bila diperlukan. Ketiganya bekerja bersama melalui browser.

Contoh Sederhana

Sebuah tombol memiliki elemen HTML, gaya CSS, dan event JavaScript untuk merespons klik.

Coba pikirkan: jika input, ukuran data, kondisi, atau lingkungan diubah, bagian mana dari proses yang ikut berubah? Sebelum menjalankan task, buat prediksi terlebih dahulu.

Istilah Penting

HTML, CSS, JavaScript, DOM, browser, event, responsive

Pahami istilah tersebut sebagai konsep yang saling berhubungan, bukan daftar hafalan. Saat membaca task, coba tunjukkan istilah mana yang sedang digunakan dan apa buktinya dari hasil program/scene.

Kapan Konsep Ini Digunakan?

Gunakan pembagian tanggung jawab ini agar kode lebih mudah dipahami dan dipelihara.

Pemilihan teknik selalu bergantung pada masalah. Tidak ada satu metode yang paling benar untuk semua situasi; bandingkan kebutuhan, batasan, data, dan hasil yang diinginkan.

Hal yang Perlu Diperhatikan

  • Perhatikan struktur HTML, ukuran layar, aksesibilitas, validasi input, dan jangan mengandalkan tampilan sebagai satu-satunya sumber kebenaran.
  • Uji lebih dari satu kondisi, termasuk kasus normal dan kasus batas.
  • Amati hasil sebelum mengubah kode/scene agar perubahanmu memiliki alasan.
  • Bedakan masalah pada konsep, data/input, dan implementasi.

Kesalahan Umum

Kesalahan umum: terlalu banyak inline style/script, struktur HTML tidak semantik, layout hanya cocok di satu ukuran layar, tidak memberi label input, dan tidak menguji keyboard/mobile.

Jika hasil task berbeda dari prediksi, jangan langsung mengganti kode secara acak. Cari langkah pertama ketika perilaku mulai berbeda, lalu jelaskan penyebabnya.

Cara Belajar Sebelum Task

  1. Jelaskan konsep dengan kata-katamu sendiri.
  2. Perhatikan contoh dan prediksi hasilnya sebelum dijalankan.
  3. Kerjakan task tanpa menyalin jawaban langkah demi langkah.
  4. Ubah satu bagian dan amati dampaknya.
  5. Catat alasan solusi yang kamu pilih.

1. Mengapa Dokumentasi Sangat Penting?

Developer hebat dinilai bukan hanya dari berjalannya aplikasi, melainkan seberapa bersih kodenya dan seberapa jelas panduannya agar orang lain bisa menggunakannya.

Bagian README Informasi yang Ditulis
Judul & Deskripsi Nama web app dan penjelasan singkat tentang apa fungsinya.
Fitur Utama Daftar kemampuan kuis (misal: skor instan, pilihan ganda, tombol reset).
Cara Menjalankan Petunjuk membuka website (cukup buka index.html di browser).
Pembuat Nama lengkap pembuat dan asal sekolah.
File README.md adalah buku panduan pertama yang dibaca saat orang lain membuka repositori kodinganmu.

2. Contoh File README.md Sederhana

# Kuis Cerdas Web Development Aplikasi web kuis interaktif seputar HTML, CSS, dan JavaScript untuk siswa SMA/SMK. ## Fitur: - Kuis interaktif dengan skor real-time - Tata letak responsif di layar ponsel dan desktop - Peringatan warna untuk jawaban benar dan salah ## Cara Menggunakan: 1. Buka file `index.html` menggunakan browser Google Chrome atau Firefox. 2. Pilih salah satu jawaban dari pertanyaan yang tampil di layar. 3. Nilai akhir akan muncul di bagian bawah kuis. ## Dibuat Oleh: - Nama: [Nama Siswa] - Kelas: [Kelas / Sekolah]

3. Eksplorasi Praktik

1

Rapikan indentasi file HTML, CSS, dan JS

Gunakan fitur format otomatis di code editor (Shift + Alt + F di VS Code) agar spasi dan tab tersusun lurus.

2

Hapus sisa kode uji coba

Bersihkan baris console.log() yang tidak lagi dibutuhkan dan buang potongan kode yang tidak terpakai.

3

Beri komentar penjelas

Tambahkan 1–2 baris komentar di atas fungsi penting untuk menjelaskan fungsinya secara singkat.

4

Buat file README.md

Tuliskan nama kuis, tujuan, fitur utama, dan namamu sebagai pembuat karya di folder proyek.

4. Kesalahan yang Sering Terjadi

  • Menulis kode zig-zag tanpa indentasi spasi yang konsisten, sehingga sulit dibaca saat ada baris penutup yang kurang.
  • Menyimpan puluhan komentar dari kode gagal lama yang membuat file menjadi penuh dan membingungkan.
  • Tidak mencantumkan identitas dan penjelasan fitur pada file proyek.
Kode yang bersih (Clean Code) mencerminkan ketelitian dan profesionalisme seorang programmer.
