Uji dan Perbaikan Bug

Menemukan error pada panel Console, menguji skenario tak terduga, dan memastikan aplikasi bebas masalah

Materi Lengkap: Pengembangan Halaman Web

Konsep dasar. Pengembangan web menggabungkan struktur halaman, tampilan, dan perilaku interaktif. HTML mendefinisikan makna dan struktur, CSS mengatur presentasi, sedangkan JavaScript mengatur logika di browser. Pada materi Uji dan Perbaikan Bug, fokus utama kita adalah pengembangan halaman web. Tujuannya bukan menghafal langkah, tetapi memahami alasan di balik setiap keputusan sehingga kamu dapat menerapkannya pada masalah yang berbeda.

Cara kerja. Halaman web dibangun dari struktur HTML, aturan visual CSS, dan perilaku JavaScript bila diperlukan. Ketiganya bekerja bersama melalui browser.

Contoh Sederhana

Sebuah tombol memiliki elemen HTML, gaya CSS, dan event JavaScript untuk merespons klik.

Coba pikirkan: jika input, ukuran data, kondisi, atau lingkungan diubah, bagian mana dari proses yang ikut berubah? Sebelum menjalankan task, buat prediksi terlebih dahulu.

Istilah Penting

HTML, CSS, JavaScript, DOM, browser, event, responsive

Pahami istilah tersebut sebagai konsep yang saling berhubungan, bukan daftar hafalan. Saat membaca task, coba tunjukkan istilah mana yang sedang digunakan dan apa buktinya dari hasil program/scene.

Kapan Konsep Ini Digunakan?

Gunakan pembagian tanggung jawab ini agar kode lebih mudah dipahami dan dipelihara.

Pemilihan teknik selalu bergantung pada masalah. Tidak ada satu metode yang paling benar untuk semua situasi; bandingkan kebutuhan, batasan, data, dan hasil yang diinginkan.

Hal yang Perlu Diperhatikan

  • Perhatikan struktur HTML, ukuran layar, aksesibilitas, validasi input, dan jangan mengandalkan tampilan sebagai satu-satunya sumber kebenaran.
  • Uji lebih dari satu kondisi, termasuk kasus normal dan kasus batas.
  • Amati hasil sebelum mengubah kode/scene agar perubahanmu memiliki alasan.
  • Bedakan masalah pada konsep, data/input, dan implementasi.

Kesalahan Umum

Kesalahan umum: terlalu banyak inline style/script, struktur HTML tidak semantik, layout hanya cocok di satu ukuran layar, tidak memberi label input, dan tidak menguji keyboard/mobile.

Jika hasil task berbeda dari prediksi, jangan langsung mengganti kode secara acak. Cari langkah pertama ketika perilaku mulai berbeda, lalu jelaskan penyebabnya.

Cara Belajar Sebelum Task

  1. Jelaskan konsep dengan kata-katamu sendiri.
  2. Perhatikan contoh dan prediksi hasilnya sebelum dijalankan.
  3. Kerjakan task tanpa menyalin jawaban langkah demi langkah.
  4. Ubah satu bagian dan amati dampaknya.
  5. Catat alasan solusi yang kamu pilih.

1. Membaca Pesan Error di Tab Console

Bug adalah kesalahan dalam kode yang menyebabkan aplikasi macet atau tidak bekerja sebagaimana mestinya. Tab Console pada browser Developer Tools (F12) adalah alat utama untuk melihat pesan kesalahan tersebut.

Pesan Error Umum Penyebab Utama Cara Memperbaiki
Uncaught TypeError: Cannot read properties of null JavaScript mencoba mengakses elemen HTML yang tidak ditemukan id/class-nya Periksa kesamaan ejaan nama id atau class antara HTML dan JavaScript
Uncaught ReferenceError: ... is not defined Variabel atau fungsi dipanggil padahal belum pernah dibuat namanya Cek deklarasi variabel atau ejaan huruf besar/kecil fungsi
NaN (Not a Number) Operasi matematika dijalankan pada teks yang bukan angka Pastikan input dibungkus fungsi Number() dan tidak bernilai kosong
Developer profesional selalu menguji skenario di luar dugaan: apa yang terjadi jika tombol diklik berkali-kali dengan cepat, atau jika kolom isian dibiarkan kosong?

2. Menulis Kode Aman (Defensive Code)

// 1. Cek keberadaan elemen sebelum dipasangi listener const btnReset = document.querySelector("#btnReset"); if (btnReset) { btnReset.addEventListener("click", () => { totalSkor = 0; perbaruiTampilanSkor(totalSkor); }); } else { console.warn("Tombol reset tidak ditemukan pada halaman ini."); }

3. Eksplorasi Praktik

1

Buka Developer Tools Console

Tekan tombol F12 atau klik kanan lalu pilih Inspect, kemudian buka tab Console.

2

Uji coba tombol dan input

Gunakan aplikasi kuis, klik tombol opsi, dan periksa apakah ada teks merah error yang muncul di panel Console.

3

Uji skenario batas (Edge Cases)

Coba klik tombol beberapa kali berturut-turut untuk memastikan skor tidak terus bertambah secara curang.

4

Pastikan status 0 Error

Perbaiki baris kode yang memicu error sampai tab Console bersih dan aplikasi berjalan stabil.

4. Kesalahan yang Sering Terjadi

  • Mengabaikan pesan error merah di console selama tampilan website terlihat masih bisa diklik.
  • Hanya menguji skenario sukses (skenario yang berjalan normal) tanpa menguji saat pengguna salah input.
  • Memperbaiki satu baris kode tetapi secara tidak sengaja menghapus kurung kurawal tutup (}) yang memicu SyntaxError baru.
Jika menemukan error di Console, klik tautan nomor baris di sebelah kanan pesan error untuk langsung melompat ke baris kode yang bermasalah.
