Game Loop, Audio 3D & AI Musuh

Loop permainan, suara berdasarkan jarak, dan musuh yang mengejar atau berpatroli

Materi Lengkap: Game Loop Dan Waktu

Konsep dasar. Pengembangan 3D mengatur objek dalam ruang tiga dimensi. Setiap objek memiliki posisi, rotasi, skala, dan dapat berinteraksi dengan kamera, cahaya, fisika, audio, serta logika permainan. Pada materi Game Loop, Audio 3D & AI Musuh, fokus utama kita adalah game loop dan waktu. Tujuannya bukan menghafal langkah, tetapi memahami alasan di balik setiap keputusan sehingga kamu dapat menerapkannya pada masalah yang berbeda.

Cara kerja. Game loop menjalankan pembaruan logika secara berulang. Delta time membantu membuat gerak berbasis waktu sehingga lebih konsisten pada frame rate berbeda.

Contoh Sederhana

Posisi += kecepatan × deltaTime membuat perpindahan bergantung pada durasi, bukan jumlah frame.

Coba pikirkan: jika input, ukuran data, kondisi, atau lingkungan diubah, bagian mana dari proses yang ikut berubah? Sebelum menjalankan task, buat prediksi terlebih dahulu.

Istilah Penting

game loop, frame, delta time, update, fixed update, frame rate

Pahami istilah tersebut sebagai konsep yang saling berhubungan, bukan daftar hafalan. Saat membaca task, coba tunjukkan istilah mana yang sedang digunakan dan apa buktinya dari hasil program/scene.

Kapan Konsep Ini Digunakan?

Gunakan untuk gerak, timer, cooldown, animasi, dan sistem real-time.

Pemilihan teknik selalu bergantung pada masalah. Tidak ada satu metode yang paling benar untuk semua situasi; bandingkan kebutuhan, batasan, data, dan hasil yang diinginkan.

Hal yang Perlu Diperhatikan

  • Perhatikan koordinat, parent-child transform, collider, frame rate, jarak kamera, dan perbedaan update per frame dengan waktu nyata.
  • Uji lebih dari satu kondisi, termasuk kasus normal dan kasus batas.
  • Amati hasil sebelum mengubah kode/scene agar perubahanmu memiliki alasan.
  • Bedakan masalah pada konsep, data/input, dan implementasi.

Kesalahan Umum

Kesalahan umum: salah memahami sumbu, gerak bergantung frame rate, collider tidak sesuai bentuk, terlalu banyak objek/efek, dan tidak menguji scene pada kondisi performa berbeda.

Jika hasil task berbeda dari prediksi, jangan langsung mengganti kode secara acak. Cari langkah pertama ketika perilaku mulai berbeda, lalu jelaskan penyebabnya.

Cara Belajar Sebelum Task

  1. Jelaskan konsep dengan kata-katamu sendiri.
  2. Perhatikan contoh dan prediksi hasilnya sebelum dijalankan.
  3. Kerjakan task tanpa menyalin jawaban langkah demi langkah.
  4. Ubah satu bagian dan amati dampaknya.
  5. Catat alasan solusi yang kamu pilih.

1. Game loop dan dt

let waktuLalu = 0; function loop(waktuSekarang) { const dt = (waktuSekarang - waktuLalu) / 1000; // detik waktuLalu = waktuSekarang; bacaInput(); update(dt); gambar(); requestAnimationFrame(loop); } requestAnimationFrame(loop);

Setiap putaran: input → update → gambar. Semua yang bergerak memakai dt agar kecepatannya stabil.

2. Penghitung waktu

let sisa = 60; // detik function update(dt) { if (selesai) return; sisa -= dt; if (sisa <= 0) { sisa = 0; selesai = true; pesan = "Waktu habis!"; } } // tampil: Math.ceil(sisa) + " detik"

Tampilkan sisa waktu supaya pemain bisa merencanakan langkah. Waktu habis adalah salah satu syarat kalah.

3. Musuh pengejar

const dx = pemain.x - musuh.x, dz = pemain.z - musuh.z; const jarak = Math.sqrt(dx*dx + dz*dz); if (jarak > 1.5) { // berhenti saat dekat musuh.x += dx / jarak * kecepatanMusuh * dt; musuh.z += dz / jarak * kecepatanMusuh * dt; }
dx / jarak adalah arah satuan menuju pemain. Kalikan dengan kecepatan dan dt untuk jarak langkah per frame.
Beri musuh kecepatan sedikit di bawah kecepatan lari pemain supaya permainan tetap adil.
