Kontrol Karakter

Gerak, kamera, lompat, dan animasi sederhana

Materi Lengkap: World Building Dan Interaksi 3D

Konsep dasar. Pengembangan 3D mengatur objek dalam ruang tiga dimensi. Setiap objek memiliki posisi, rotasi, skala, dan dapat berinteraksi dengan kamera, cahaya, fisika, audio, serta logika permainan. Pada materi Kontrol Karakter, fokus utama kita adalah world building dan interaksi 3D. Tujuannya bukan menghafal langkah, tetapi memahami alasan di balik setiap keputusan sehingga kamu dapat menerapkannya pada masalah yang berbeda.

Cara kerja. Scene 3D dibangun dari objek, transformasi, kamera, pencahayaan, material, dan logika interaksi. Setiap elemen memiliki peran sehingga dunia terasa konsisten dan dapat dimainkan.

Contoh Sederhana

Desa mini dapat terdiri dari rumah, jalan, pohon, kamera, karakter, collider, dan pencahayaan.

Coba pikirkan: jika input, ukuran data, kondisi, atau lingkungan diubah, bagian mana dari proses yang ikut berubah? Sebelum menjalankan task, buat prediksi terlebih dahulu.

Istilah Penting

scene, object, transform, material, collider, camera, lighting

Pahami istilah tersebut sebagai konsep yang saling berhubungan, bukan daftar hafalan. Saat membaca task, coba tunjukkan istilah mana yang sedang digunakan dan apa buktinya dari hasil program/scene.

Kapan Konsep Ini Digunakan?

Gunakan saat membangun level, simulasi, atau game 3D.

Pemilihan teknik selalu bergantung pada masalah. Tidak ada satu metode yang paling benar untuk semua situasi; bandingkan kebutuhan, batasan, data, dan hasil yang diinginkan.

Hal yang Perlu Diperhatikan

  • Perhatikan koordinat, parent-child transform, collider, frame rate, jarak kamera, dan perbedaan update per frame dengan waktu nyata.
  • Uji lebih dari satu kondisi, termasuk kasus normal dan kasus batas.
  • Amati hasil sebelum mengubah kode/scene agar perubahanmu memiliki alasan.
  • Bedakan masalah pada konsep, data/input, dan implementasi.

Kesalahan Umum

Kesalahan umum: salah memahami sumbu, gerak bergantung frame rate, collider tidak sesuai bentuk, terlalu banyak objek/efek, dan tidak menguji scene pada kondisi performa berbeda.

Jika hasil task berbeda dari prediksi, jangan langsung mengganti kode secara acak. Cari langkah pertama ketika perilaku mulai berbeda, lalu jelaskan penyebabnya.

Cara Belajar Sebelum Task

  1. Jelaskan konsep dengan kata-katamu sendiri.
  2. Perhatikan contoh dan prediksi hasilnya sebelum dijalankan.
  3. Kerjakan task tanpa menyalin jawaban langkah demi langkah.
  4. Ubah satu bagian dan amati dampaknya.
  5. Catat alasan solusi yang kamu pilih.

1. Gerak = mengubah posisi tiap frame

Game menggambar ulang puluhan kali per detik. Setiap frame, kita menggeser posisi karakter sedikit: posisi baru = posisi lama + arah × kecepatan × dt. dt adalah waktu sejak frame sebelumnya, supaya kecepatan sama di komputer cepat maupun lambat.

const kecepatan = 4; // satuan per detik function update(dt) { let ax = 0, az = 0; if (tombol.W) az -= 1; if (tombol.S) az += 1; if (tombol.A) ax -= 1; if (tombol.D) ax += 1; const panjang = Math.sqrt(ax*ax + az*az); if (panjang > 0) { ax /= panjang; az /= panjang; } // normalisasi karakter.x += ax * kecepatan * dt; karakter.z += az * kecepatan * dt; }
TombolArahSumbu
WMajuZ berkurang (di banyak engine, depan = -Z)
SMundurZ bertambah
AKiriX berkurang
DKananX bertambah
Tanpa normalisasi, berjalan diagonal (W+D) lebih cepat sekitar 1,4 kali. Arah depan bisa berbeda di tiap engine, jadi cek dengan mencoba.
Contoh kode memakai pseudokode mirip JavaScript agar konsepnya berlaku di engine 3D apa pun. Nama fungsi di editor atau engine yang dipakai kelasmu bisa berbeda; pahami logikanya, lalu cari padanannya.

2. Kamera yang mengikuti karakter

const offset = { x: 0, y: 3, z: 6 }; // di belakang dan di atas kamera.x = karakter.x + offset.x; kamera.y = karakter.y + offset.y; kamera.z = karakter.z + offset.z; kamera.lihatKe(karakter.x, karakter.y + 1, karakter.z);
PengaturanEfek
Jarak (z) besarPemandangan luas, karakter tampak kecil
Tinggi (y) besarPandangan dari atas, mudah melihat rintangan
Terlalu dekatSulit melihat sekitar, mudah pusing

Agar kamera tidak kaku, geser pelan menuju target: kamera.x += (target - kamera.x) * 5 * dt.

3. Lompat

const gravitasi = -20, kekuatanLompat = 8; if (tombol.Spasi && diTanah) { vy = kekuatanLompat; diTanah = false; } vy += gravitasi * dt; karakter.y += vy * dt; if (karakter.y <= tinggiTanah) { karakter.y = tinggiTanah; vy = 0; diTanah = true; }
Tinggi lompatan maksimum kira-kira kekuatan² ÷ (2 × gravitasi). Contoh: 8² ÷ (2 × 20) = 1,6 satuan. Mengubah kekuatan lompat atau gravitasi langsung mengubah tinggi.
Syarat diTanah mencegah lompat berkali-kali di udara.

4. Animasi sederhana: diam vs bergerak

const bergerak = (ax !== 0 || az !== 0); if (bergerak) { waktu += dt; karakter.badan.y = Math.sin(waktu * 10) * 0.05; // naik-turun saat jalan } else { karakter.badan.y = 0; // diam }

Cukup satu perbedaan jelas antara diam dan bergerak (goyang, miring, ukuran) supaya karakter terasa hidup. Lihat dari depan dan samping untuk memeriksa bagian yang masih kaku.

6. Peta ke task

  • Karakter bergerak: bagian gerak dan normalisasi.
  • Kamera ikut: offset kamera.
  • Lompat: gravitasi dan rumus tinggi lompat.
  • Animasi karakter: perbedaan diam dan bergerak.
  • Atur kecepatan: tabel jalan dan lari.
